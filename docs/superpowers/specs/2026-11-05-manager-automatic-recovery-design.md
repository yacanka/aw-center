# Manager automatic preparation and recovery

The user wants to click once on a restricted-network Windows machine and let
Manager exhaust safe available options before requesting assistance. A screenshot
of bundle/online remaining at Hazırlık does not establish a network failure:
source admission and lock acquisition currently precede any progress event.

Keep the current launcher pipeline, Tk UI and isolated workers. Use the existing
restricted policy as the desktop default: verified local media/cache, selected
repositories, then approved public sources. Corporate and offline remain explicit
boundaries. Prefer available verified local packages in every mode. Retry truncated
transfers and recognize explicit transient package-manager failures; never mask
TLS, checksum, permissions, disk, cancellation or installation failures.

Reuse verified runtime archives across full-package stages without mutating live
tools. Validate bundle output before preparing tools. Manager supplies a unique
new output directory when blank and treats a selected existing directory as a
parent for a unique package, preserving all existing files. CLI output semantics
stay unchanged. Report each real phase, safe attempt/fallback information, and
an actionable final error only after permitted alternatives are exhausted.

Reuse system-first tool selection; do not replace recorded interpreter bindings,
override an explicit tool path, silently migrate existing data, or change ACLs.
Administrator credentials, production IPv4/TLS, trusted CA/proxy access, damaged
media and migration consent remain real user needs. No new dependency, service,
background framework, arbitrary mirror, global tool installation or publication.

Native EXE/NTFS/ACL/LockFileEx acceptance still requires Windows. Local mocked
transport tests prove recovery policy, not success on the photographed computer.
